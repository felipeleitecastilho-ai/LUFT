1. Visão Geral do Projeto

Este projeto criou um Data Lakehouse na Luft Logistics.

O que foi construído:

  • Ingestão automática de 4 fontes de dados (Oracle, API, SQL Server, CSVs)
  • 37 tabelas Bronze com dados brutos no Snowflake
  • Transformações automáticas via Dynamic Tables (Silver e Gold)
  • Agente de IA que responde perguntas financeiras e operacionais

Arquitetura: Bronze → Silver → Gold → Agente

Os scripts ficam no servidor Windows da Luft.

Localização: C:\Users\keyrus\etl_luft\

3.2 Como rodar manualmente

Abra o Prompt de Comando e digite:

cd C:\Users\keyrus\etl_luft
python etl_protheus.py
python etl_silt.py
python etl_tms.py

3.3 Rodar apenas uma tabela

Use o parâmetro --apenas para rodar uma tabela específica:

python etl_silt.py --apenas=NF_ENTRADA
python etl_tms.py --apenas=OCORRENCIAS_SAC_TMS_RAW

3.4 Se der erro

Passos para resolver erros:
  1. Verificar o painel Streamlit ou a tabela ETL_LOG
  2. Rodar manualmente o script que falhou
  3. Erros comuns:
    • Timeout API: esperar 5 minutos e tentar de novo
    • SQL Server offline: verificar se o servidor TMS está acessível na rede

4.2 Silver (dados limpos) SILVER

13 Dynamic Tables que atualizam automaticamente.

  • Conversão de tipos: texto → data, texto → número
  • Limpeza: TRIM, padronização de nomes
  • Não precisa de ação manual. Atualizam sozinhas.

4.3 Gold (dados para consumo) GOLD

Camada final. É o que os usuários consultam.

  • Views semânticas para o agente de IA
  • Dynamic Tables agregadas (DRE, Razão, Frota)
  • Nomes de colunas amigáveis e em português

View principal de Compras: VW_COMPRAS_PROTHEUS

  • 45 campos enriquecidos (JOINs com Empresas, Fornecedor, Produtos)
  • Dados direto do ERP com fornecedor, CNPJ, conta contábil, centro de custo

5. Cortex Agent (DRE_FILIAIS)

O agente de IA responde perguntas sobre a Luft.

Ele tem 7 ferramentas. Cada uma responde um tipo de pergunta.

FerramentaO que respondeExemplos de perguntas
Analista_FinanceiroEBITDA, receita, custos, margem"Qual o EBITDA de Barueri?"
Analista_FrotaKm rodados, combustível, custo/km"Qual o custo por km?"
Analista_Frota_CadastroVeículos, placas, modelos"Quantos veículos próprios?"
Analista_EmpilhadeiraEquipamentos, locação"Custo total de locação?"
Analista_Razao_LogisticoLançamentos contábeis"Maiores gastos por conta?"
Analista_ContratosVigência, reajuste, SLA"Quando vence o contrato X?"
Analista_ComprasFornecedores, produtos, valores"Qual fornecedor compro mais?"

Como funciona:

  1. Você faz uma pergunta em linguagem natural
  2. O agente identifica qual ferramenta usar
  3. A ferramenta consulta a semantic view correta
  4. Retorna a resposta com dados reais do Snowflake
Dica: Quanto mais específica a pergunta, melhor a resposta. Inclua filial, período ou métrica.

8. Como Adicionar Novos Dados

8.1 Adicionar dados em tabela que já existe

A maioria das tabelas CSV tem um Snowpipe configurado. Basta subir o arquivo na pasta correta e a carga é automática.

  1. Converter o arquivo para CSV (UTF-8, separador vírgula, com header)
  2. Subir para o stage na pasta da tabela: 
    PUT file://C:/caminho/arquivo.csv @DRE_AGENTE_ALL.BRONZE.STG_LANDING/pasta/;
  3. Pronto! O Snowpipe detecta e carrega sozinho.

Pastas configuradas com Snowpipe:

Cuidado: O CSV precisa ter as mesmas colunas e na mesma ordem. Se mudou o formato, verifique com: DESCRIBE TABLE nome_tabela;

8.2 Nova planilha CSV (tabela nova)

  1. Converter para CSV (UTF-8, separador vírgula)
  2. Subir para o stage: 
    PUT file://C:/caminho/arquivo.csv @DRE_AGENTE_ALL.BRONZE.STG_LANDING/pasta/;
  3. Criar tabela Bronze com colunas VARCHAR
  4. Carregar dados com COPY INTO

8.3 Nova fonte API/banco

  1. Criar script Python seguindo padrão dos existentes
  2. Adicionar chamada no executar_etl.bat
  3. Testar manualmente antes de automatizar

8.4 Levar até o agente

  1. Criar View Gold com nomes amigáveis em português
  2. Criar Semantic View com FACTS e DIMENSIONS
  3. Recriar o agente com CREATE OR REPLACE AGENT ... FROM SPECIFICATION $$ YAML $$
  4. Re-aplicar GRANT USAGE no agente para cada role
  5. Testar no Snowsight (aba Preview) antes de liberar
Atenção: Fazer backup da spec do agente ANTES de alterar. O CREATE OR REPLACE apaga grants e versões anteriores.

9. Manutenção Diária

Checklist para verificar todo dia útil:

  • Verificar painel Streamlit (cargas do dia ok?)
  • Se alerta de falha chegou por email, investigar
  • Verificar se warehouse ETL_WH está suspenso (economia de créditos)
Dica: Se tudo aparece verde no painel, não precisa fazer nada.

Glossário

Bronze
Dados brutos, como vieram da fonte. Sem transformação.
Silver
Dados limpos e com tipos corretos (datas, números).
Gold
Dados prontos para análise. Camada final.
Dynamic Table
Tabela que atualiza sozinha quando a fonte muda.
Semantic View
Camada que ensina o agente a entender os dados.
Stage
Área temporária para upload de arquivos no Snowflake.
ETL
Processo de Extrair, Transformar e Carregar dados.
Full load
Apaga tudo e recarrega do zero.
Incremental
Carrega apenas dados novos desde a última execução.
